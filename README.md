# Курсы Банка России

Консольное приложение для получения и расчёта официальных валютных курсов Банка России, определения изменения курса
относительно предыдущего опубликованного набора и асинхронной загрузки исторических данных.

**Стек:** PHP 8.4, Symfony 7.4, PostgreSQL 18, Redis, RabbitMQ, Doctrine DBAL, BCMath, Docker Compose.

## Быстрый запуск

Для запуска необходимы Docker и Docker Compose 2.24.4 или новее. PHP и Composer на хосте не требуются. Все команды
выполняются из корня репозитория.

### 1. Запустить приложение

```bash
docker compose up --build -d --wait --wait-timeout 600
```

При каждом запуске приложение безопасно проверяет и применяет миграции, затем проверяет доступность PostgreSQL, Redis и
RabbitMQ. Worker и Dispatcher запускаются только после успешной инициализации.

### 2. Получить курс USD/RUB

```bash
docker compose exec app php bin/console app:rates:get USD --date=2026-10-24
```

Дата указывается в формате `YYYY-MM-DD`. Также поддерживаются `DD.MM.YYYY`, `DD/MM/YYYY` и `DD-MM-YYYY`.

По умолчанию базовая валюта — `RUR`, которая нормализуется в `RUB`. Другую базовую валюту можно указать через `--base`:

```bash
docker compose exec app php bin/console app:rates:get USD --base=EUR --date=2026-10-24
```

### 3. Загрузить историю

```bash
docker compose exec app php bin/console app:rates:import
```

По умолчанию регистрируются последние 180 календарных дней, заканчивающиеся вчерашней датой по московскому времени.

Для собственного периода или количества дней:

```bash
docker compose exec app php bin/console app:rates:import --from=2026-10-01 --to=2026-10-24
docker compose exec app php bin/console app:rates:import --days=30 --progress
```

Опция `--yes` автоматически подтверждает корректировку периода, если он выходит за допустимые границы источника. Опция
`--progress` показывает ход фоновой обработки.

### 4. Остановить приложение

```bash
docker compose down
```

Данные PostgreSQL, Redis и RabbitMQ сохраняются в Docker volumes.

## Консольные команды

Все команды выполняются через:

```bash
docker compose exec app php bin/console <command>
```

Если вы уже находитесь внутри контейнера `app`, достаточно выполнить `php bin/console <command>`.

### Получение курса — `app:rates:get`

```bash
# Прямой курс USD/RUB
docker compose exec app php bin/console app:rates:get USD --date=2026-10-24

# Кросс-курс INR/USD
docker compose exec app php bin/console app:rates:get INR --base=USD --date=2026-10-24

# Ответ в формате JSON
docker compose exec app php bin/console app:rates:get USD --date=2026-10-24 --format=json

# Курс на текущую календарную дату
docker compose exec app php bin/console app:rates:get USD
```

| Параметр   | Описание                                         |
|------------|--------------------------------------------------|
| `currency` | Код валюты, обязательный аргумент                |
| `--base`   | Базовая валюта, по умолчанию `RUR`               |
| `--date`   | Календарная дата, по умолчанию сегодня по Москве |
| `--format` | `table` по умолчанию или `json`                  |

Результат содержит дату запроса, дату действия официального курса, номинал и котировку ЦБ, текущий и предыдущий курсы, а
также изменение курса.

### Импорт истории — `app:rates:import`

```bash
# Импорт 180 календарных дней
docker compose exec app php bin/console app:rates:import

# Импорт указанного периода
docker compose exec app php bin/console app:rates:import --from=2026-10-01 --to=2026-10-24

# Импорт 30 дней с отображением прогресса
docker compose exec app php bin/console app:rates:import --days=30 --progress

# Наблюдать за прогрессом не более 120 секунд
docker compose exec app php bin/console app:rates:import --days=30 --progress --progress-timeout=120
```

| Опция                   | Описание                                                         |
|-------------------------|------------------------------------------------------------------|
| `--days=N`              | Количество календарных дней                                      |
| `--from=DATE`           | Начало периода                                                   |
| `--to=DATE`             | Конец периода                                                    |
| `--yes`                 | Подтвердить корректировку периода без вопроса                    |
| `--progress`            | Отображать ход импорта                                           |
| `--progress-interval=N` | Интервал обновления прогресса в секундах                         |
| `--progress-timeout=N`  | Ограничение времени наблюдения в секундах; `0` — без ограничения |

Границы периода включаются в импорт. `--days` можно использовать с одной из границ `--from` или `--to`.

Команда только регистрирует задания. Непосредственную загрузку выполняют Dispatcher и Worker в фоновом режиме.
Завершение наблюдения по `--progress-timeout` не останавливает импорт. Повторная регистрация уже загруженного периода не
приводит к повторной загрузке подтверждённых дат.

### Ошибки импорта

Просмотр терминальных ошибок:

```bash
docker compose exec app php bin/console app:rates:errors
```

Поддерживаются `--date=YYYY-MM-DD` для конкретной даты и `--limit=N` для ограничения количества строк.

Повторная обработка одного задания:

```bash
docker compose exec app php bin/console app:rates:retry-errors --date=2026-10-24
```

Повторная обработка всех ошибочных заданий:

```bash
docker compose exec app php bin/console app:rates:retry-errors --all --yes
```

Временные ошибки обрабатываются автоматически. Задания в терминальном состоянии `Error` требуют ручного восстановления.

### Дополнительные команды

```bash
# Принудительное обновление курса
docker compose exec app php bin/console app:rates:refresh --date=2026-10-24

# Однократный запуск Dispatcher
docker compose exec app php bin/console app:rates:dispatch --once

# Проверка готовности инфраструктуры
docker compose exec app php bin/console app:health:ready
```

Dispatcher в режиме `--watch` автоматически запускается через Docker Compose.

## Бизнес-правила и принятые соглашения

### Календарная дата и дата действия курса

Банк России возвращает официальные курсы на дату действия, которая может отличаться от запрошенной календарной даты. В
выходные и праздничные дни несколько календарных дат могут ссылаться на один опубликованный набор.

Для определения изменения курса используется предыдущий отличный официальный набор, а не обязательно предыдущий
календарный день. Его поиск выполняется относительно даты действия текущего набора.

### Минимальная дата

Исторические курсы ЦБ доступны с 01.07.1992. В приложении минимальной датой запроса установлена **03.07.1992**,
поскольку для расчёта изменения курса необходим предыдущий официальный набор.

Запросы на будущие даты не допускаются. Календарные даты определяются в часовом поясе `Europe/Moscow`.

### Номинал и кросс-курсы

При расчёте учитываются `Value` и `Nominal` из официальных котировок ЦБ.

Для кросс-курсов обе валюты пересчитываются через рубль:

```text
Курс валюты к RUB = Value / Nominal

CUR / BASE = (CUR / RUB) / (BASE / RUB)
```

`RUR` и `RUB` в приложении обозначают российский рубль.

### Точность вычислений

Вычисления выполняются через `BcMath\Number` без использования `float`. Для деления применяется внутренняя точность до
**30 знаков после десятичной точки**.

Изменение курса рассчитывается из неокруглённых значений. При формировании ответа числа округляются для удобства
отображения. Поэтому отображаемая разница может не совпадать с результатом вычитания двух уже округлённых курсов.

### Валидация валют

Коды валют проверяются на соответствие трёхбуквенному формату, но дополнительная сверка со справочником ISO 4217 не
выполняется.

Фактическая доступность валюты определяется официальным набором курсов Банка России. Если валюта отсутствует в
необходимом наборе, приложение возвращает ошибку.

### Исторические XML-ответы

Для совместимости с историческими ответами ЦБ отдельные неполные записи валют, не содержащие обязательных полей,
пропускаются.

Остальные корректные котировки сохраняются. Если после обработки набор не содержит допустимых котировок, он отклоняется.

### Кеширование

Данные запрашиваются в следующем порядке:

```text
Redis → PostgreSQL → API Банка России
```

После получения из внешнего источника котировки сначала сохраняются в PostgreSQL, затем кешируются в Redis.

PostgreSQL хранит официальные наборы и точные соответствия календарных дат. Redis используется для кеширования,
распределённых блокировок загрузки и глобального ограничения частоты обращений к API.

### Асинхронный импорт

Импорт выполняется через PostgreSQL Jobs, RabbitMQ и Symfony Messenger.

| Состояние    | Значение                  |
|--------------|---------------------------|
| `Waiting`    | Ожидает обработки         |
| `Processing` | Обрабатывается Worker     |
| `Deferred`   | Ожидает повторной попытки |
| `Done`       | Успешно завершено         |
| `Error`      | Терминальная ошибка       |

Для защиты от повторной и устаревшей обработки используются версии заданий, lease и проверки актуальности исполнения.
Временные ошибки переводят задание в `Deferred`; постоянные ошибки, включая конфликт сохранённых данных, завершают его в
`Error`.

### Глобальный Rate Limiter

Для ограничения нагрузки на API Банка России используется глобальный Rate Limiter на базе Redis и Symfony RateLimiter.

Ограничение действует на все экземпляры приложения, включая консольные команды и фоновые Worker. Используется алгоритм
Token Bucket с ёмкостью 2 токена и пополнением 1 токен в секунду — до 60 запросов в минуту при непрерывной нагрузке.

Общий лимит контролирует совокупную интенсивность обращений независимо от количества запущенных Worker. Токен требуется
только для реального запроса к внешнему API: чтение уже сохранённого RateSet из Redis или PostgreSQL лимит не расходует.

Если токен недоступен, Worker откладывает задание без расходования попытки. Интерактивная CLI-команда повторяет
временную ошибку в пределах общего бюджета ожидания 5 секунд, после чего завершается предсказуемой ошибкой.

## Архитектура

Приложение разделено на бизнес-модули и общую инфраструктуру:

```text
app/src/
├── Courses/         # Получение, хранение и расчёт валютных курсов
├── Import/          # Регистрация и асинхронная обработка заданий
├── Shared/
│   ├── Contracts/   # Межмодульные контракты
│   └── Domain/      # Общие типы дат
└── Support/         # Rate Limiter, Retry, Health, Logging
```

Внутри модулей используется разделение на `Domain`, `Application`, `Infrastructure` и `Endpoints`:

- **Domain** — бизнес-модели, инварианты и расчёты.
- **Application** — сценарии использования и контракты.
- **Infrastructure** — PostgreSQL, Redis, RabbitMQ и HTTP-интеграции.
- **Endpoints** — консольные команды и обработчики сообщений.

Модуль `Import` взаимодействует с `Courses` через `Shared/Contracts`. Зависимости между слоями контролируются Deptrac.
Для работы с PostgreSQL используется Doctrine DBAL без ORM.

Сервис `app` применяет миграции и выполняет readiness-проверку. После успешной инициализации он остаётся доступным для
ручных CLI-вызовов. Worker обрабатывает сообщения Messenger, а Dispatcher планирует и публикует задания импорта.

Приложение не содержит HTTP-сервера и HTTP-маршрутов.

## Разработка

Запуск окружения с bind mount исходного кода:

```bash
make dev
```

Или непосредственно через Docker Compose:

```bash
docker compose -f compose.yaml -f compose.dev.yaml up --build -d --wait --wait-timeout 600
```

В dev-окружении доступен Xdebug. Исходный код приложения располагается в `app/`, журналы — в `app/var/log/`.

Production-образ содержит готовые зависимости без Composer, dev-зависимостей и Xdebug.

## Тестирование

```bash
# Полный набор Unit, Integration и E2E
make test

# Только Unit-тесты
make test a="--testsuite Unit"

# PHP CS Fixer, PHPStan max, Deptrac
make qa

# Первоначальный production-like запуск и перезапуск приложения
make test-startup
```

Тесты выполняются в изолированном Docker Compose-окружении с PostgreSQL, Redis, RabbitMQ и CBR Stub. `make test-startup`
проверяет production-образ, автоматическое применение миграций, readiness gate и безопасный повторный запуск.

## Известные ограничения

- **Установка:** начальная миграция `Version20261101000000` предназначена для первоначального создания чистой базы
  PostgreSQL и не обновляет старые варианты схемы.
- **Конкуренция за Rate Limiter:** интерактивные запросы и фоновый импорт используют общий бюджет обращений к ЦБ. При
  интенсивном импорте токены могут быть заняты Worker, поэтому CLI-запрос может ожидать освобождения лимита или
  завершиться ошибкой после бюджета ожидания 5 секунд. Приоритет CLI над фоновыми заданиями не реализован. Возможная
  доработка — резервирование части пропускной способности или приоритеты при сохранении общего ограничения нагрузки.
- **Refresh и Redis:** при конкурентном обновлении возможна поздняя запись устаревшего значения в кеш. Для полного
  устранения требуется дополнительное согласование операций инвалидации и кеширования.
- **Исторические котировки:** отдельные неполные XML-записи пропускаются по принятой политике совместимости с данными
  источника.
- **Точность отображения:** вычисления выполняются с внутренней точностью 30 знаков, а округление применяется на границе
  вывода; отображаемый diff может отличаться от вычитания двух уже округлённых значений.
- **Исходные данные:** в PostgreSQL сохраняются структурированные котировки; отдельный архив исходных XML-ответов не
  ведётся.
- **Интерфейс:** приложение предоставляет CLI-команды; HTTP API не реализован.
