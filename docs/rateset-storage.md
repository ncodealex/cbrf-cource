# Получение и хранение официальных наборов курсов ЦБ

Актуальная реализация этого этапа находится в `App\Cources`. Контракты расположены в `Application/Contract`, доменные объекты — в `Domain/Entity`. Предыдущая расширенная спецификация `exchange-rate-spec.md` описывает также будущие механизмы и не определяет текущую схему хранения.

## Использование

Внедрите `App\Cources\Application\Service\RateSetResolver` через конструктор:

```php
$rateSet = $resolver->resolve(MoscowCalendar::date('2026-10-26'));
```

`requestDate` — календарная дата: учитывается `Y-m-d` переданного DatePoint, время отбрасывается. Для текущей даты используйте `MoscowCalendar::dateOf($clock->now())`: календарь переводит момент времени в `Europe/Moscow`.

Resolver сначала читает Redis, затем PostgreSQL. Только отсутствие подтверждённой связи в БД приводит к запросу ЦБ. Ответ сохраняется в БД, после успешного сохранения заполняется Redis. Все источники возвращают существующий доменный `RateSet`.

`effectiveDate` определяется атрибутом `ValCurs.Date`, а не календарём выходных. Например, запрос на 26 октября может вернуть набор от 24 октября. Поддерживается предварительное сохранение последнего опубликованного набора:

```php
$rateSet = $gateway->fetchLatest();
$repository->save($rateSet->effectiveDate, $rateSet);
```

`fetchLatest()` не передаёт `date_req`. Дата действия может наступить завтра.

## PostgreSQL

Миграция `Version20261030000000` создаёт:

| Таблица | Столбцы |
| --- | --- |
| `rate_sets` | `effective_date DATE PRIMARY KEY`, `rates JSONB NOT NULL`, `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()` |
| `rate_request_dates` | `requested_date DATE PRIMARY KEY`, `effective_date DATE NOT NULL REFERENCES rate_sets(effective_date)` |

Один набор хранится на одну дату действия. Несколько дат запроса ссылаются на него без дублирования котировок. `created_at` устанавливается при первой вставке. Таблицы обслуживаются DBAL и миграцией; ORM SchemaTool исключает их через `schema_filter`.

`save()` использует одну транзакцию PostgreSQL с обычным уровнем изоляции READ COMMITTED. Для каждой таблицы выполняется INSERT с `ON CONFLICT DO NOTHING RETURNING`. При конфликте отдельный SELECT читает зафиксированную конкурентную запись. Для набора сравнивается `contentHash()`, для календарной связи — дата действия. Идентичные записи означают успех, различие вызывает `RateSetConflict` и откат всей операции. UPDATE, предварительного SELECT и дополнительных блокировок нет.

`get()` ищет только точное соответствие `requested_date`. Отсутствие связи вызывает `RateSetNotFound`; ближайшая дата не подбирается. Хэш вычисляется в памяти и отдельно не хранится.

## Представление данных и Redis

Общий `RateSetMapper` преобразует набор в структуру `effectiveDate` + список `items`. Каждый элемент содержит `code`, `sourceId`, `nominal`, `value`, `name`, `numCode`. В JSONB сохраняется список `items`, дата берётся из столбца; в Redis — полная структура.

`value` — строка, например `"81.4500"`. Восстановление через `BcMath\Number` сохраняет scale и завершающие нули. Исходная стоимость номинала не заменяется стоимостью одной единицы. `numCode` также остаётся строкой, включая ведущие нули.

Redis использует зарегистрированный сервис `Redis` и ключ `rateset:date:YYYY-MM-DD`. Значение записывается как JSON атомарной командой SET с EX. `CACHE_DEFAULT_TTL` задаёт положительный TTL в секундах; по умолчанию в шаблоне окружения — 3600. Один набор может находиться в нескольких ключах.

Отсутствующий ключ вызывает `RateSetNotFound`. Недоступность Redis, ошибка команды или повреждённый payload вызывают `RateSetCacheFailure`. Resolver логирует ошибку кеша и продолжает получение данных. Ошибка записи Redis не отменяет зафиксированное сохранение PostgreSQL.

## Gateway и ошибки

`CbrRateSetGateway` использует существующий scoped HttpClient `cbr.client`: таймаут ожидания 5 секунд, максимальная длительность 15 секунд. `CBR_BASE_URL` по умолчанию равен `https://www.cbr.ru`.

XML десериализуется Symfony Serializer в `RateSetResponse` с коллекцией `RateItemResponse`. XML-имена связаны со свойствами через `#[SerializedName]`; дата, номинал, числовой код и значение котировки остаются строками. `RateSetResponseDenormalizer` приводит единственный `Valute` к списку, после чего штатный ObjectNormalizer создаёт вложенные DTO. Для определения типов коллекции PHPDoc Extractor доступен в production-зависимостях.

`CbrRateSetResponseMapper` проверяет DTO, преобразует дату, номинал и значение, затем создаёт доменные объекты. Он отделён от общего `RateSetMapper` PostgreSQL/Redis, поскольку отвечает за внешний формат ЦБ.

XML разбирается с учётом объявленной кодировки, без подстановки внешних сущностей, с отключённой сетью и запретом DTD. Короткая DOM-проверка сохраняет требование корня `ValCurs`, имя которого XmlEncoder не включает в результат. Даты, обязательные поля, номиналы и decimal strings проверяются. Дубли валют, рубль и пустой набор отклоняются доменными конструкторами. `VunitRate` игнорируется.

- `CbrUnavailable`: transport failure, timeout и HTTP-ответы кроме 200/429.
- `CbrRateLimited`: HTTP 429.
- `CbrInvalidResponse`: пустой ответ, некорректный XML или валютные данные.
- `RateSetConflict`: попытка изменить набор или подтверждённое соответствие дат.

Ошибки БД, конфликты и ошибки ЦБ передаются вызывающему коду. Автоматических повторов HTTP нет. Логи Gateway содержат краткий контекст без полного XML.

## Проверки

Из корня репозитория:

```sh
make test
make test a="--testsuite Unit"
make test a="--testsuite Integration"
make qa
```

Тестовое окружение создаёт отдельную БД, запускает миграции и использует подмену HTTP, без реальных обращений к ЦБ. Тесты Repository создают уникальные схемы `rateset_test_*` и удаляют только собственные схемы после проверки. Конкурентность проверяется отдельным PHP-процессом: тест дожидается реального ожидания блокировки уникальности PostgreSQL, затем фиксирует первую транзакцию. Redis-тесты используют отдельные ключи с TTL и очищают их.

Для ручного PHPStan сначала выполните `php bin/console cache:warmup --env=test`: анализ использует XML-контейнер тестового окружения и обнаруживает классы миграций через `scanDirectories`.

## Следующий этап

Scheduler, RabbitMQ handlers, backfill, Import Coordinator, распределённые блокировки и ограничитель частоты запросов не реализованы. Два одновременных cache miss могут вызвать два HTTP-запроса, но сохранение остаётся идемпотентным и атомарным. Оригинальные XML, ревизии и отдельные версии JSON не хранятся.
